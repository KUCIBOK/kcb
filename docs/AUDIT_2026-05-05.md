## 4. Code paiement (sur `dev`, pas encore en prod)

### Fix webhook PayDunya (commit `420cf47`)

Le bug critique: depuis la cutover M3 vers Supabase, **100% des callbacks PayDunya legitimes etaient rejetes en 403** parce que le code lisait le hash dans `req.headers['paydunya-hash']` et le comparait a `PAYDUNYA_MASTER_KEY` brute. La doc PayDunya (API PAR section IPN) precise que:
- Le hash arrive dans le body form-urlencoded sous `data.hash`
- C'est `SHA-512(MasterKey)`, pas la master key elle-meme

Consequences avant fix:
- Tout achat d'oeuvre paye sur PayDunya restait sans trace en base
- L'oeuvre n'etait pas marquee vendue
- Aucun recu envoye
- L'admin ne voyait jamais qui avait essaye de payer

Trois changements dans le commit:
1. **Hash check corrige** (lecture body, comparaison `createHash('sha512').update(MASTER_KEY).digest('hex')`)
2. **Insert `pending` au lancement** dans `routePaydunyaInit`. Chaque tentative laisse une trace meme si elle n'aboutit pas.
3. **UPDATE plutot qu'INSERT au callback** (avec INSERT en fallback pour les paiements legacy sans ligne pending)

### Checkout invite (commit `420cf47` cote backend, `7ec1e6a` cote frontend)

Backend:
- `routePaydunyaInit` n'exige plus l'auth pour `type='artwork'`
- Accepte un bloc `guest: { name, email, phone? }` dans le body si pas de session
- Forward les infos guest vers PayDunya (`invoice.customer`) et dans `custom_data`
- Insert la ligne pending avec `buyer_email`, `buyer_phone`, `buyer_name`
- Abonnements continuent d'imposer l'auth (un sub est lie a un user)

Frontend (`src/pages/ArtworkCheckout.jsx`):
- Affiche un form (nom + email + tel optionnel) quand l'utilisateur n'est pas connecte
- Validation email cote client
- Bouton "Payer" plus jamais bloque par "Vous devez etre connecte"
- Lien vers `/sign-in` pour ceux qui preferent un compte

### Validation Niveau A (test sans cout)

Pour confirmer que le fix marche apres deploy preview:
```bash
# Body vide (pas de field "data"), test discriminant
curl -X POST '<PREVIEW_URL>/api/payments/paydunya-callback' \
  -H 'Content-Type: application/json' -d '{}'
```

Reponse attendue:
- Code bugge (avant deploy): `403 "Signature webhook invalide"`
- Code fixe (apres deploy): `400 "Donnees PayDunya manquantes"`

Pour le test complet avec hash valide, il faut soit le sandbox PayDunya (Niveau B), soit un test e2e avec carte de test.

### D. Cron expiration abonnements (priorite moyenne)

3 abonnements `active` ont leur `end_date` depasse depuis le 2026-04-08. Aucun job ne les flippe automatiquement vers `expired`. A mettre en place cote Vercel Cron Jobs:

```ts
// /api/cron/expire-subscriptions
await sb.from('subscriptions')
  .update({ status: 'expired' })
  .eq('status', 'active')
  .lt('end_date', new Date().toISOString());
```

Schedule quotidien, ex. `0 2 * * *`.
